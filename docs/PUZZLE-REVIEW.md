# Review every puzzle before children play

Open **Einstellungen** through its existing adult calculation, then tap **Puzzle-Prüfung öffnen**. The review opens directly, without another calculation. **Puzzle-Galerie öffnen** is separate: it lists only puzzles signed off for children, with a tab per friend on top, and a card plays a normal round of five tasks (never saved as the child's round, never completing a letter, not observed by the usage log; `js/screens/puzzle-gallery.js`). A direct review URL still asks once before opening. Published reviews live on GitHub and restore automatically across browsers/installations. Nothing is preapproved.

## Inspect and decide

1. The entry page shows all 31 puzzles and the single **Prüfung auf GitHub** connection panel. Choose a puzzle to open its details, including a plain-language competence explanation, curriculum reference, fixed difficulty and iteration progress. The header back arrow returns to all puzzles; from there it returns to Settings. Use **Spielerklärung anhören** to test the one shared spoken rule for that puzzle. The complete rule text is also shown. Speech is requested only by that button; individual iteration previews have no repeated speech control. Normal child play keeps **Spiel erklären**.
2. Press **Offene Iterationen prüfen**. The queue contains every currently unconfirmed iteration of that puzzle, including items marked for improvement and changed revisions. It is not limited to five. The task area has exactly the normal game's viewport; there is no sign-off footer. The counter shows your position in the queue and the five leaves show overall progress.
3. Solve the task normally. Wrong answers remain editable. A correct answer saves that iteration's approval, shows the usual correct feedback for 900 ms and advances automatically. Handwriting requires completing every stroke. There is no separate approval button.
4. The small **×** replaces the normal rule-speech control. It opens **Kommentar (optional)** and **Ablehnen und weiter**. Reject with or without a comment; the item stays marked **Verbessern**. **Weiter prüfen**, the dialog close button or Escape cancels without making a decision. Rejections appear once in this run and return in the next run, avoiding an endless loop.
5. After the final iteration, the normal friend/leaf/flower celebration plays for 2.2 seconds. Once all current iterations passed and their decisions are saved on GitHub, the puzzle is released. The celebration also records the historical puzzle-level completion. Rejected items keep it blocked; leaving the celebration retains every saved iteration decision.
6. **Zur Puzzle-Prüfung** returns to the selected puzzle. You can also select a particular iteration from the list, including an approved item you want to inspect again. It appears first, followed by that puzzle's remaining unconfirmed items. Refreshing or reopening starts a fresh queue of only the still-unconfirmed items.

Each puzzle also has an optional **Allgemeiner Kommentar zum Puzzle** field and **Kommentar speichern**. After a successful save the field is empty and the submitted comment appears under **Bisherige Hinweise**. Earlier comments remain there; returning to the puzzle does not prefill an already submitted note. Unsaved text stays available while navigating and filtering during the visit. Comments sync through GitHub and preserve the underlying approval/rejection, revision and original history; submitting a comment does not approve or reject anything.

**Bisherige Hinweise** has an accessible **×** beside each comment, including notes from earlier revisions. It removes that comment and its older duplicates without changing any approval, rejection, revision or inspection evidence. Deletions are saved locally first and sync to GitHub through the same connection as decisions. A reload or another browser does not restore a deleted note after sync. Unsaved general-comment drafts remain available. Saving a new comment later is still allowed.

**Bisherige Hinweise** collects earlier notes from every graphics/content revision, including notes recovered from GitHub on a fresh browser. Original dates and **Frühere Version** distinguish them from current decisions. **Aktuelle Aufgabe ansehen** opens the same stable iteration in its current form. Restoring or reading a note does not approve the current task or upload a decision. The [15 November follow-up](PUZZLE-FEEDBACK-2026-11-15.md) and [17 November follow-up](PUZZLE-FEEDBACK-2026-11-17.md) map the original notes to the current implementation.

Only puzzles whose current iterations are **all approved and confirmed on GitHub** enter play. A changed iteration keeps that puzzle open until it passes; unchanged iterations retain their decisions. A separate repeat of the whole-puzzle sign-off is unnecessary. Explicit iteration or puzzle rejections still block release. Filters show pending, improvement, approved and changed items. The overview omits curriculum codes; the selected puzzle retains its detailed curriculum reference and a general competence heading.

## Save, restore and revisit

[Connect GitHub once per editing session](REVIEW-STORAGE.md) on the Puzzle-Prüfung entry page to save changes automatically. Other browsers and fresh installations read the shared file without a token. A local-only decision does not release a puzzle for children. Wait for **Auf GitHub gespeichert** before deleting local storage; offline changes remain in the outbox until uploaded.

There is no file export/import any more: GitHub is the backup. Each puzzle offers **Alle bestätigen** to approve all its current iterations and the puzzle together (after a confirmation), as an alternative to playing each one. Earlier decisions stay in the history. New decisions contain no reviewer/checklist fields.

The shared file is [reviews.json on puzzle-review-data](https://github.com/MrTolchock/Drawing-App/blob/puzzle-review-data/reviews.json). The offline cache and outbox use `farbtupf.puzzle-review.v1`. The GitHub token is held separately in session storage and is never exported or committed. Development reviews with `?dev=1` stay local and do not publish.

New iterations start open. Changed questions, applicable difficulty/instructions, interaction, typography and actual image cells reopen only affected iterations. Unrelated items, adult menus, competence summaries, curriculum references and list labels preserve approvals. The puzzle stays open until every current iteration is approved; adding content cannot inherit a previous approval. Old decisions remain in history or marked stale. A deployment does not sign off anything.

Since 9.3.94 the generated implementation contains individual presentation fingerprints and verified historical revision aliases for all 958 iterations. Each compatibility proof is bound to the current exact task revision; an edited question or image cannot reuse stale aliases. Historical files are compared per iteration, restoring unchanged parts of previously edited puzzles read-only. See [iteration-level review and adult menus](PUZZLE-REVIEW-ITERATIONS-2026-11-18.md).

Verified historical implementation revisions remain valid for unchanged puzzles. The fingerprint builder compares each puzzle's finite questions, reachable rendering and actual picture cells against Git history; an unused empty-basket branch cannot reopen unrelated games. Compatibility includes the complete historical per-puzzle implementation token. The narrowly recorded return to the original nut picture is an explicit owner-requested restoration; all other atlas cells must match. See [9.3.93 recovery](PUZZLE-REVIEW-RECOVERY-2026-11-17.md). Recovery reads the original GitHub records without changing their dates, creating decisions or uploading them. Later rejections or withdrawals on the same stable task still block release, including those from another application revision. Historical rejections remain marked **Verbessern** with their changed-version marker and notes. Deleted comments stay deleted.

## Developer process

Work on a branch and push checkpoints. Publish to main when the owner authorizes it. Follow the [visual style](../design/VISUAL-STYLE.md) and [puzzle blueprint](../design/PUZZLE-BLUEPRINT.md), reuse the real renderers and give new iterations stable IDs and explicit solutions/difficulty.

Run `node tools/puzzle-catalogue.cjs` after runtime/content/art changes. Commit its generated catalogue and implementation fingerprint. If the fingerprint builder changes, regenerate the historical baselines with that same builder first; the generated metadata rejects a different builder digest. Run the model, design, review and journey checks described in [Development](DEVELOPMENT.md); review fixtures live only in disposable test contexts. The review browser suite checks all 31 puzzle-level speech requests, correct-answer approvals, optional rejections, whole-pool queues, real touch/mouse input, backup compatibility, production-sized layouts, revision gates and isolated child saves. `tests/review-sync-browser.cjs` covers real UI saves and restoration across independent browser storage, plus offline edits and conflict resolution. `tests/review-recovery-browser.cjs` checks historical compatibility, the playable gallery, later comments/restrictions, deletion markers and offline restoration with no writes. Tests intercept GitHub requests and never use a real token or publish fixture approvals.

Preserve storage keys and historical snapshots. Bump the app/cache version for changed cached runtime files. No approval data ships with the app. The [catalogue](PUZZLE-CATALOGUE.md) lists every puzzle, competence and exact iteration definition; CI checks its revisions and generated pages.
